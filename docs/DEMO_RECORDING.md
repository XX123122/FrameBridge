3. Show the original prompt file and task packet with personal paths/reference details redacted. Show explicit task approval.
4. Record one real Send, observation and normal preview/download without cuts implying a second Send never occurred. Real delays may be accelerated, but label the speed/cuts and state measured times accurately.
5. Show the local output and `check` result, with original prompt preserved and no overwrite. Timing is observed UI time, not server compute.
6. Review every frame for sensitive information; use irreversible redaction before exporting. Keep the source private. Confirm consent to publish any references/generated content.
7. Add the reviewed asset under docs/assets with origin/date/tool version, media rights, redactions, task scope and alt text. Link it from both README demo sections only after approval.
