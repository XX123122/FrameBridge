# 下载流程优化

> 历史维护者试验记录。测量仅适用于这些案例，不代表新用户权限、当前浏览器状态或固定模型速度。开源发布状态见 [RELEASE_READINESS.md](RELEASE_READINESS.md)。

日期：2026-10-13。范围：减少本地准备、预览与保存的人工介入，不额外生图，不改变模型、账号或 Prompt。

## 已实现

- 新任务只需 `generate ID --confirmed`：准备图片模式、一次提交、观察、保存使用同一次 Edge 连接。已完成/非 pending/输出存在/缺少确认会在浏览器接入前拒绝。
- 直接点击唯一已生成预览按钮，不悬停试探；点击一次后等待唯一 dialog，再等待唯一可用下载按钮。分别有 8 秒上限，等待期间检查验证/额度/权限，不重发请求或重复打开预览。
- 每秒观察生成完成；保留完整的身份/Prompt/唯一结果核对和 1 秒稳定复核。未生成完成时先检查画廊状态，省掉反复读取整个对话文本的操作。
- stderr 实时报告提交、等待、预览、下载、保存阶段，等待时每 15 秒报告一次；stdout 为最终结果。
- 自动生成任务耗时 JSON/Markdown，恢复保持原首次完成时间，不把恢复等待重新计为生成耗时。
- 浏览器测试复用一个测试进程，每个案例仍使用独立 context 与本地任务目录，全部外部请求拦截。减少测试浏览器启动次数，不复用用户登录档。

## 验证

完整测试：**43 项全部通过，26.521 秒，无跳过**。覆盖延迟打开 dialog、延迟加载下载按钮、下载按钮暂不可用、预览缺失只点击一次、等待期间遇验证停止、一条 generate 只连接/提交一次、耗时报告自动保存、恢复时间保留、原图禁止覆盖与已有对话禁止误发等。

真实网页复测使用已完成的 K02，未点击发送或请求新图片：关闭当前查看器，在原对话重新打开其唯一图像预览，点击正常下载，保存到临时文件，完整解码与 SHA-256 对照原图，随后清理临时文件。

结果：**0.859 秒**，指已完成图片的“重新打开预览 → 下载 → 文件/哈希校验”。这是收集阶段，不包含模型生成；与旧 K02 的 152.588 秒总耗时范围不同，不能直接换算成模型加速百分比。

原 K02 与 K01 文件和生成耗时记录保持不变。复测报告在本地 `logs/K02/optimization-download-check.json`；SHA-256 与原 K02 一致：`108dabfad6064e45194148cf789be70dda467d5e4fdcde23fc929a000e07b755`。

## 优化后的完整真实任务

用户随后明确授权 K03 生成一只猫猫。单条 generate 命令完成全部流程，无失败、重发或人工恢复：

| 项目 | 实测 |
| --- | --- |
| 发送至页面首次生成完成 | 46.485 秒 |
| 预览、下载与文件验证 | 1.828 秒 |
| 发送至保存完成 | 49.453 秒 |
| 提交 / 恢复 | 1 次 / 0 次 |
| 输出 | PNG，1374×1145，2,211,575 字节 |

使用单调时钟，1 秒轮询，另做 1 秒完成复核；耗时不含发送前的任务准备。完整数据自动写入本地 `logs/K03/timing.json` 与 `timing.md`，未人工补写计时。K01/K02 输出未改动。

这证明新版完整流程可自动完成；K02 与 K03 的 Prompt 不同，且 K02 总耗时含人工修复，因此不能把这组差异解释为模型计算加速比例。
